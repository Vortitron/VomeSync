VomeSync Security Audit

Generated: 2026-01-25

Scope: Home Assistant integration access control (owner vs subscription), delegated access keys, and toggle permissions. This audit focuses on preventing unauthorised toggling and ensuring that authorised toggles propagate correctly.

Summary

Access control for toggle operations is now enforced in two layers: owner-only signed state changes and delegated access keys for subscriptions. Subscribed switches are read-only by default (sensor entities), and only become controllable when a valid access key is provided.

Threat Model

Unauthorised toggle via subscription
  • Risk: A subscriber could toggle without permission.
  • Mitigation: Subscriptions create sensors only (read-only) unless access key exists.
  • Mitigation: Coordinator rejects non-owner state changes.
Key misuse or wrong permissions
  • Risk: Access keys without toggle permission could be used.
  • Mitigation: Server enforces requireV2AccessKey('toggle') for toggle endpoint.
  • Mitigation: Access-key toggles fail if server rejects key/permission.
State desynchronisation across owners/subscribers
  • Risk: Toggle by one party does not propagate.
  • Mitigation: WebSocket broadcasts and local state updates on toggle response.
  • Mitigation: Subscriptions maintain WebSocket connections per UID.

Security Controls

Owner-only write path
  • Owner state changes use signed v2 endpoint: /api/v2/switch/:uid/state.
  • HA coordinator refuses non-owner state changes.
Delegated access keys for subscriptions
  • Non-owner toggles use /api/v2/switch/:uid/toggle with X-Api-Key.
  • HA allows subscription toggling only when an access key is stored.
  • Subscriptions without access keys are sensors (read-only).
Entity safeguards
  • Switch entities are created only for owners or subscriptions with access keys.
  • Existing subscription switch entities are disabled if no access key exists.

Webserver enforcement
  • V2 toggle endpoint requires delegated access key with toggle permission.
  • Owner state endpoint requires valid signed payload and nonce.

Residual Risks

Access key storage in HA
  • Access keys are stored in HA config options; protect Home Assistant backups and storage.
Access key revocation
  • Revoked keys will cause toggles to fail; UI will remain but actions are denied server-side.

Recommendations

Operational guidance
  • Encourage users to back up signing keys via the new integration menu.
  • Document access key revocation and its impact on HA entities.
  • Keep Redis and HA storage protected; treat keys as secrets.
